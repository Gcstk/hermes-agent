# 时间与复杂度评估

## 估算标尺来源

这个文件把行业常用的软件规模/复杂度/工期估算方法转成学习计划可用的版本。

参考标尺：

- ISO/IEC 20926 IFPUG Function Point Analysis：正式功能规模度量标准，衡量用户可见功能规模，而不是代码行数。来源：https://www.iso.org/standard/51717.html
- ISO/IEC 19761 COSMIC：正式功能规模度量标准，适用于业务软件、实时软件及混合系统。来源：https://www.iso.org/standard/33899.html
- COCOMO II：用规模、scale factors、effort multipliers 估算软件建设成本和进度。来源：https://www.rose-hulman.edu/class/cs/csse372/201310/Homework/CII_modelman2000.pdf
- McCabe Cyclomatic Complexity：用独立执行路径衡量控制流复杂度，常用于测试和维护风险判断。来源：https://ieeexplore.ieee.org/iel1/2837/6079/00237006.pdf
- Cognitive Complexity：更偏“人读代码有多难”的复杂度指标，关注控制流嵌套和理解负担。来源：https://www.sonarsource.com/docs/CognitiveComplexity.pdf
- Agile Story Points：相对估算方法，通常综合工作量、复杂度、风险和不确定性。来源：https://www.atlassian.com/agile/project-management/estimation

适用边界：

- ISO Function Point / COSMIC 适合估“要建设多少功能”，不适合直接估“读源码要多久”。
- COCOMO II 适合估软件开发成本，不适合直接估学习成本，但它提醒我们：规模、复杂度、风险、团队熟悉度都会放大工期。
- Cyclomatic/Cognitive Complexity 适合判断“读这段代码有多吃力”。
- Story Points 适合做相对估算。学习计划采用 Fibonacci 点数：1、2、3、5、8、13、20。

## 本计划使用的学习复杂度模型

每个模块给出四个指标：

- 代码规模：主要阅读文件的大致行数。
- 复杂度等级：C1 到 C5。
- 学习点数：Fibonacci story points。
- 预计时间：包含读实现、读关键测试、画图和写学习笔记。

复杂度等级：

| 等级 | 含义 | 典型特征 |
|---|---|---|
| C1 入门 | 局部、短文件、低耦合 | < 800 行，单一职责，测试直接 |
| C2 基础 | 多文件但链路清楚 | 800-2500 行，少量回调/配置 |
| C3 中等 | 跨模块，需要读测试理解边界 | 2500-7000 行，有缓存、状态、插件或兼容路径 |
| C4 高 | 核心生命周期或高恢复复杂度 | 7000-15000 行，多 provider/tool/history 交互 |
| C5 很高 | 系统级专题，横跨核心、插件、测试和 surface | >15000 行，高不确定性，高上下文切换 |

学习点数到时间的粗略映射：

| 点数 | 时间盒 | 说明 |
|---|---|---|
| 1 | 0.5-1 小时 | 浏览级 |
| 2 | 1-2 小时 | 小模块 |
| 3 | 2-4 小时 | 一个清晰子系统 |
| 5 | 4-7 小时 | 半天到一天 |
| 8 | 7-12 小时 | 一到两天 |
| 13 | 12-20 小时 | 两到三天 |
| 20 | 20-35 小时 | 一周级专题 |

假设：

- 你有 Python 基础，并愿意边读测试边画图。
- 每天有效学习 2-3 小时。
- 时间不包含真实改代码，只包含理解、复盘和做小实验。
- 如果你已经熟悉 agent harness，可把时间乘以 0.7；如果 Python/异步/LLM tool calling 不熟，乘以 1.4。

## 关于“是不是一定要 9 周”

不一定。9 周不是必需工期，而是“深度掌握路线”的一个保守时间盒。这里的深度掌握指：

- 能从用户输入追踪到 `AIAgent`、turn context、模型调用、工具执行、压缩、持久化、memory sync 和 finalizer。
- 能用 harness 语言解释 Hermes 的 action space、observation、recovery、context budget 和 side-effect control。
- 能把 skills、memory、自进化、subagent/multi-agent、超长程任务这些功能放回同一张架构图里。
- 能指出关键工程取舍：prompt caching 为什么神圣、工具 schema 为什么要收束、dynamic context 为什么不进 system prompt、后台线程/锁/增量持久化保护了什么。
- 能输出自己的架构复盘和迁移方案，而不是只输入源码信息。

如果目标只是“知道 Hermes 怎么跑”，1-2 周足够。  
如果目标是“能讲清核心机制”，3-4 周更现实。  
如果目标是“能在自己的 agent 项目里借鉴 harness 工程”，6-9 周更稳。  
如果目标是“能参与核心维护和复杂 bug 评审”，10-12 周并不夸张。

## 分阶段时间评估

| 阶段 | 主题 | 复杂度 | 点数 | 预计时间 | 主要风险 |
|---|---|---:|---:|---:|---|
| 0 | 环境与仓库导航 | C1 | 2 | 1-2h | Windows 环境、命令差异 |
| 1 | 一轮对话主链路 | C4 | 13 | 12-18h | loop 很长，恢复分支多 |
| 2 | prompt、role alternation、prompt caching | C3 | 8 | 7-12h | API-only 与 durable history 容易混 |
| 3 | 工具系统与 harness | C4 | 13 | 12-20h | registry、toolsets、dispatch、guardrails 跨文件 |
| 4 | SessionDB、搜索、compression | C4-C5 | 20 | 20-30h | DB、FTS、压缩边界、并发 lock |
| 5 | skills 系统 | C4 | 13 | 12-20h | skill discovery、frontmatter、安全边界、usage 状态 |
| 6 | memory 系统 | C3-C4 | 13 | 10-18h | provider hooks、后台 sync、插件差异 |
| 7 | 自进化闭环 | C4 | 13 | 12-20h | `/learn`、skill_manage、curator、backup 组合理解 |
| 8 | 委派、多 agent、自动化 | C4-C5 | 20 | 18-30h | subagent、budget、cron、kanban、MoA 交叉 |
| 9 | surface 交互边界 | C3 | 5 | 4-8h | 容易滑进前端细节 |
| 10 | 综合复盘 | C4 | 8 | 8-12h | 需要把多个专题串成一张图 |

总时间：

- 快速路线：约 3-4 周，每周 10-12 小时，抓主干和关键测试。
- 扎实路线：约 6-8 周，每周 8-10 小时，每阶段都写笔记和图。
- 深挖路线：约 10-12 周，每周 8-10 小时，额外做小实验和读插件实现。

## 推荐学习排期

### 第 1 周：建立主干

- 阶段 0：1-2h。
- 阶段 1：12-18h 中先完成前 8h，只读主流程，不钻每个异常分支。
- 输出：`notes-01-turn-loop.md` 初版。

### 第 2 周：prompt 与 harness

- 阶段 2：7-12h。
- 阶段 3：先读 `tools/registry.py`、`model_tools.py`、`toolsets.py`，约 6-8h。
- 输出：prompt cache 图、tool schema 生成图。

### 第 3 周：工具恢复与上下文

- 阶段 3 剩余：tool_executor、tool_guardrails、error recovery，约 6-10h。
- 阶段 4 开始：只读 `context_compressor.py` 主符号和测试，约 6-8h。
- 输出：tool recovery matrix。

### 第 4 周：session 与压缩

- 阶段 4 完整完成：`hermes_state.py` + compression tests，约 14-22h。
- 输出：session/compression 生命周期图。

### 第 5 周：skills

- 阶段 5：12-20h。
- 输出：skill 生命周期图，说明 slash command、skill_view、skill_manage、skill_usage 的边界。

### 第 6 周：memory

- 阶段 6：10-18h。
- 输出：MemoryProvider hook 图，比较 Honcho/mem0/supermemory 接入方式。

### 第 7 周：自进化

- 阶段 7：12-20h。
- 输出：自进化闭环图，重点说明 guard 和 rollback。

### 第 8 周：委派与 surface

- 阶段 8：选读 12-18h，不必一次吃完整个 kanban。
- 阶段 9：4-8h。
- 输出：subagent/delegation 图，surface 边界图。

### 第 9 周：综合复盘

- 阶段 10：8-12h。
- 输出：总架构图和 1500-3000 字复盘。

## 每阶段结束的验收口径

每个阶段必须交付：

- 一张流程图。
- 一张“关键文件职责表”。
- 一张“测试保护行为表”。
- 三条不变量。
- 两个你认为可以借鉴到自己 agent 项目的设计。
- 一个仍不确定的问题。

## 时间控制规则

- 单个文件阅读超过 90 分钟还没有形成流程图，就停止通读，改读测试。
- 单个阶段超过预计上限 30%，必须缩小范围，只保留主链路。
- 巨型文件不按行读，按符号和测试驱动读。
- 每次学习最多保留 3 个未解问题，多出来的放到 backlog，避免打断主线。
