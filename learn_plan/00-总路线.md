# Hermes Agent 核心学习总路线

## 学习目标

把 Hermes 当作一个现代 agent harness 来学习，而不是只读一个聊天机器人：

- 先读懂一轮对话如何从用户输入进入 agent loop，再到工具调用、恢复、压缩、持久化和最终响应。
- 再读懂能力如何被放在边缘：tools、toolsets、plugins、skills、memory providers，而不是堆进核心。
- 最后读懂它的出彩点：prompt caching 保护、skills 作为过程记忆、memory provider 抽象、自进化闭环、工具面 harness 设计、错误恢复和上下文预算。

## 当前学习边界

主线：

- `run_agent.py`
- `agent/`
- `model_tools.py`
- `toolsets.py`
- `tools/`
- `hermes_state.py`
- `skills/`
- `plugins/memory/`
- 与核心交互必要的 `cli.py`、`hermes_cli/commands.py`、`gateway/run.py`、`tui_gateway/server.py`

暂不深入：

- `apps/desktop/`
- `web/`
- `website/`
- `ui-tui/` 的 React/Ink 细节

但需要知道：这些 surface 最终都在复用同一套 agent core、slash command、gateway/session/tool 机制。

## 推荐节奏

严格按“链路优先，专题后置”学习：

1. 先会画出一轮 turn 的主流程。
2. 再逐步解释每个扩展点为什么放在那里。
3. 每一阶段都用测试验证自己的理解。
4. 每学完一个模块，在 `04-学习记录模板.md` 的格式下新增一篇笔记。

## 不是固定 9 周，而是按掌握深度选路线

9 周不是最低学习时间。它对应的是“扎实掌握 + 能迁移设计”的路线：不只是看懂，还要能画图、讲清、定位测试、解释工程取舍，并把 harness 思路迁移到自己的 agent 项目里。

更合理的分层：

| 路线 | 时间 | 学完后的效果 |
|---|---:|---|
| 快速鸟瞰 | 1-2 周 | 能说清 Hermes agent core 的主链路，知道核心文件在哪 |
| 核心掌握 | 3-4 周 | 能解释 tool harness、prompt caching、skills、memory 的主要机制 |
| 扎实掌握 | 6-8 周 | 能按测试追踪关键行为，能写出架构复盘和专题设计笔记 |
| 深度掌握 | 9-12 周 | 能评审/修改类似 agent harness，能迁移 Hermes 的设计到自己的系统 |

本计划默认目标是“深度掌握”，但执行时可以先完成 3-4 周核心掌握，再决定是否继续深挖。

## 阶段总览

| 阶段 | 主题 | 核心问题 | 产物 |
|---|---|---|---|
| 0 | 仓库导航与运行方式 | 入口在哪里，测试怎么跑 | 本地命令卡片 |
| 1 | 一轮对话主链路 | user message 如何变成 final response | turn 流程图 |
| 2 | prompt 与缓存 | system prompt 为什么必须稳定 | prompt caching 笔记 |
| 3 | 工具 harness | tool schema 如何生成、裁剪、执行、恢复 | tool 调用链路图 |
| 4 | session 与压缩 | 长对话如何存储、搜索、压缩 | context 生命周期图 |
| 5 | skills 系统 | skill 如何被发现、加载、调用、创建 | skill 生命周期图 |
| 6 | memory 系统 | memory provider 如何接入 turn hooks | memory provider 图 |
| 7 | 自进化闭环 | `/learn`、skill 管理、curator 如何组合 | 自进化闭环图 |
| 8 | 多 agent/委派 | delegate、batch、kanban 如何扩展 agent | delegation 图 |
| 9 | surface 交互 | CLI/gateway/TUI/desktop 如何复用核心 | surface 边界图 |
| 10 | 综合复盘 | 用一个任务串起 skills + memory + tools | 一篇架构复盘 |

## 通过标准

每一阶段结束必须能做到三件事：

- 说清楚关键文件和函数的职责边界。
- 指出至少 2 个对应测试文件，说明它们保护的行为。
- 写一页中文笔记：流程、关键设计、踩坑点、自己仍不确定的问题。

## 学习方法

- 优先用 Serena 或符号概览看类/函数结构，避免一开始通读巨型文件。
- 读核心时先看测试名，再回到实现。Hermes 的测试文件名经常直接暴露历史 bug 和设计不变量。
- 不要把注释当噪音。这个仓库很多注释是“事故复盘”，尤其是 prompt caching、role alternation、compression、tool recovery、skills 安全边界。
- 读到一个机制，马上问：它是在保护缓存、保护工具面、保护会话历史，还是保护用户数据？
