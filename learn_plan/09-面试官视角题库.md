# 面试官视角题库：Hermes Agent 与 Harness 工程

目标：把学习提升到面试级别。你不仅要能说“我看过 Hermes”，还要能像工程负责人一样解释架构、权衡、风险、恢复路径、测试证据和迁移方案。

| 能力 | 面试官在看什么 | Hermes 证据 |

| Harness 思维 | 能否设计行动空间、观察、恢复、上下文预算 | `tools/registry.py`、`model_tools.py`、`toolsets.py`、`agent/tool_guardrails.py` |

## 面试评分标准

| 等级 | 表现 |
|---|---|
| 1 分：概念背诵 | 会说 RAG、tools、memory、agent loop，但说不出 Hermes 代码证据 |
| 2 分：源码定位 | 知道文件在哪里，能复述主链路，但讲不清设计取舍 |
| 3 分：工程理解 | 能解释为什么这么设计，能说出测试和失败模式 |
| 4 分：系统设计 | 能把 Hermes 设计迁移到自己的 agent harness，能权衡替代方案 |
| 5 分：维护者视角 | 能发现潜在 bug、提出改进、评审 PR、设计回归测试 |

面试目标：至少达到 4 分。  
维护/核心贡献目标：努力达到 5 分。

## 一面：核心理解与源码定位

### Q1：请画出 Hermes 一轮对话从用户输入到最终响应的核心链路。

面试官想考：

- 你是否能从复杂代码中抽出主链路。
- 你是否知道 `run_agent.py` 不是唯一重点。

优秀回答应包含：

- `AIAgent.run_conversation()` 转发到 `agent/conversation_loop.py`。
- `build_turn_context()` 做 turn prologue。
- 主循环构造 `api_messages`，保护 role alternation 和 prompt cache。
- 模型返回 tool_calls 时进入工具校验/执行/结果写回。
- 必要时 context compression。
- no-tool response 进入 final response 分支。
- `finalize_turn()` 处理持久化、清理、memory/session 收尾。

证据：

- `run_agent.py`
- `agent/conversation_loop.py`
- `agent/turn_context.py`
- `agent/turn_finalizer.py`
- `tests/agent/test_turn_context.py`
- `tests/run_agent/test_tool_call_incremental_persistence.py`

追问：

- `messages` 和 `api_messages` 有什么区别？
- 哪些内容会持久化，哪些只是 API-call-time？
- 为什么恢复路径不能随便插入 user message？

红旗回答：

- “就是 ReAct 循环，模型调用工具再回答。”太泛。
- 说不出 `turn_context` 和 `turn_finalizer`。
- 把 memory/plugin recall 说成直接改 system prompt。

### Q2：Hermes 为什么强调 prompt caching？它影响了哪些架构选择？

面试官想考：

- 你是否理解这是核心约束，而不是性能小优化。

优秀回答应包含：

- 长会话复用 cached prefix，system prompt 要 byte-stable。
- 动态 memory/plugin recall 注入当前 user message，不改 system prompt。
- skill slash command 作为 user message 进入，而不是动态拼进系统提示。
- context compression 是少数允许改变历史的机制，但受控。
- 工具 schema 也占 token，core tool 面必须收束。

证据：

- `agent/system_prompt.py`
- `agent/prompt_builder.py`
- `agent/prompt_caching.py`
- `agent/conversation_loop.py`
- `agent/skill_commands.py`
- `agent/memory_manager.py`
- `tests/agent/test_prompt_caching.py`
- `tests/agent/test_system_prompt_restore.py`

追问：

- 如果把每轮 memory recall 加到 system prompt，会发生什么？
- 如果 mid-conversation 切换 toolsets，会有什么成本？
- compression 为什么是例外？

红旗回答：

- 只说“省钱”，不说架构约束。
- 认为 prompt caching 与 skills/memory 无关。

## 二面：Harness 工程设计

### Q3：请用 harness 工程解释 Hermes 的工具系统。

面试官想考：

- 你是否能从“工具调用”上升到 action space 设计。

优秀回答应包含：

- `tools/registry.py` 是工具注册底座。
- 工具文件 self-register schema、handler、toolset、check_fn。
- `model_tools.py` 负责 discovery、schema cache、参数纠错、dispatch。
- `toolsets.py` 控制核心工具面和能力分组。
- `check_fn` 实现 service-gated action space。
- 错误 observation 需要能帮助模型恢复。

证据：

- `tools/registry.py`
- `model_tools.py`
- `toolsets.py`
- `agent/tool_executor.py`
- `tests/test_model_tools.py`
- `tests/test_get_tool_definitions_cache_isolation.py`

追问：

- 什么时候该新增 core tool？
- 什么时候该做 plugin、MCP、skill、CLI command？
- 工具 schema 为什么不能无限多？

红旗回答：

- “工具越多越强。”
- 不知道 `check_fn` 和 toolset 的意义。
- 只会讲 OpenAI function calling，不会讲 Hermes 的工程层。

### Q4：模型生成 invalid tool name 或 invalid JSON args，Hermes 应该怎么处理？

面试官想考：

- 你是否理解 agent runtime 要吸收模型不可靠输出。

优秀回答应包含：

- tool name 先尝试 repair，再返回模型可恢复错误。
- invalid JSON 短期重试，超限后注入 tool-role recovery result。
- 错误恢复必须保持 role alternation。
- 空工具名要特别 dampen，避免模型被文件里的 tool-call 片段诱导。
- 不应把错误直接变成 durable 假历史。

证据：

- `agent/conversation_loop.py`
- `model_tools.py`
- `agent/tool_guardrails.py`
- `tests/agent/test_empty_tool_name_loop_dampening.py`
- `tests/run_agent/test_tool_call_guardrail_runtime.py`
- `tests/run_agent/test_repair_tool_call_name.py`

追问：

- 为什么不用 synthetic user message 直接提醒模型？
- 什么时候该 retry，什么时候该 halt？
- 错误信息里应该包含什么？

红旗回答：

- “解析失败就报错结束。”
- “让模型自己再试一次就行。”但说不出 role sequence。

## 三面：并发、长进程、工程韧性

### Q5：Hermes 的并发工具执行有哪些风险？如何防？

面试官想考：

- 你是否能从功能读到工程事故。

优秀回答应包含：

- 多工具时可走 concurrent path，但 stateful/冲突工具要限制。
- 并发工具结果要按 tool_call_id 和 append order 写回。
- worker thread 需要 contextvars 隔离，避免 session/cwd 串线。
- interrupt 要能传播到 worker/subagent。
- iteration budget 需要线程安全，parent/subagent 共享预算。

证据：

- `agent/tool_executor.py`
- `agent/iteration_budget.py`
- `tools/delegate_tool.py`
- `tests/run_agent/test_run_agent.py` 中 `TestConcurrentToolExecution`
- `tests/run_agent/test_tool_executor_contextvar_propagation.py`
- `tests/run_agent/test_iteration_budget_race.py`
- `tests/run_agent/test_concurrent_interrupt.py`

追问：

- 并发执行为什么还要保持结果顺序？
- 哪些工具不应该并发？
- 如果两个 gateway session 同时写文件，最怕什么？

红旗回答：

- “Python 有 GIL，所以不用担心并发。”
- 只讲性能，不讲隔离、顺序、取消和持久化。

### Q6：长运行 agent 最容易出什么问题？Hermes 有哪些防护？

面试官想考：

- 你是否理解 CLI 单次任务和 gateway/TUI/cron 长进程的差异。

优秀回答应包含：

- stale client/connection、interrupt、token refresh、context overflow、DB lock、background thread 泄漏。
- API 调用 worker thread 保护主 loop 可中断。
- compression lock 防 concurrent compression fork。
- incremental persistence 保护工具副作用已发生但历史没记录。
- background review 要限制工具和 side effects。

证据：

- `agent/chat_completion_helpers.py`
- `agent/background_review.py`
- `agent/context_compressor.py`
- `hermes_state.py`
- `tests/agent/test_compression_concurrent_fork.py`
- `tests/run_agent/test_background_review.py`
- `tests/run_agent/test_openai_client_lifecycle.py`
- `tests/run_agent/test_tool_call_incremental_persistence.py`

追问：

- 为什么 background review fork 不能触碰外部 memory plugins？
- compression lock 保护的是同一窗口还是所有压缩？
- 如何为一个长进程 bug 写回归测试？

红旗回答：

- 只把长任务理解成“max_iterations 大一点”。

## 四面：上下文、长期记忆、自进化

### Q7：Hermes 的 memory、session search、skills 分别是什么？

面试官想考：

- 你是否能区分三种“记忆”。

优秀回答应包含：

- memory：声明式长期记忆、用户建模、偏好/事实。
- session search：历史对话检索，基于 SessionDB/FTS。
- skills：过程记忆，记录“怎么做”。
- memory provider 通过 `MemoryProvider` 抽象接入。
- skill 通过 slash command/user message 和 `skill_manage` 接入。

证据：

- `agent/memory_provider.py`
- `agent/memory_manager.py`
- `tools/session_search_tool.py`
- `agent/skill_commands.py`
- `tools/skill_manager_tool.py`
- `tests/agent/test_memory_provider.py`
- `tests/agent/test_skill_commands.py`
- `tests/agent/test_learn_prompt.py`

追问：

- 一个“用户喜欢简洁回答”的事实应该放 memory 还是 skill？
- 一个“如何发布 npm 包”的流程应该放 memory 还是 skill？
- session search 和 external memory provider 谁负责 recall？

红旗回答：

- 把 skills 当成普通文档库。
- 把 memory、RAG、session search 混成一类。

### Q8：Hermes 的自进化闭环如何避免失控？

面试官想考：

- 你是否理解 self-improving 和 uncontrolled self-modifying 的边界。

优秀回答应包含：

- `/learn` 构造普通 agent turn，不直接写文件。
- `skill_manage` 负责受控创建/编辑/patch/delete。
- `skill_usage` 记录 view/use/patch/state/pinned/archive。
- `curator` 做 stale/archive/consolidate，但 autonomous delete 很保守。
- `curator_backup` 提供 snapshot/rollback。
- background review 有工具限制和 side-effect 限制。

证据：

- `agent/learn_prompt.py`
- `tools/skill_manager_tool.py`
- `tools/skill_usage.py`
- `agent/curator.py`
- `agent/curator_backup.py`
- `agent/background_review.py`
- `tests/agent/test_curator.py`
- `tests/agent/test_curator_backup.py`
- `tests/run_agent/test_background_review_toolset_restriction.py`

追问：

- 为什么 `/learn` 不直接调用文件写入？
- pinned skill 为什么允许 patch/edit，但不允许自主删除？
- curator consolidation delete 为什么必须有吸收证据？

红旗回答：

- “让 agent 自动修改自己的 prompt/代码就能自进化。”
- 不谈 rollback、权限、审计、测试。

## 系统设计面：开放题

### 题目 A：设计一个 Agent Harness，让模型可以安全操作本地工程仓库。

优秀答案结构：

1. Action space：read/search/write/terminal/test/approval。
2. Observation：结构化结果、错误恢复提示、artifact 路径。
3. Context budget：系统提示稳定、按需加载技能、压缩长历史。
4. Side-effect control：路径限制、写入审批、危险命令拦截、checkpoint。
5. Long-horizon：session DB、resume、iteration budget、background review。
6. Evaluation：completion rate、tool retry、test pass、cost per success。

Hermes 借鉴点：

- `tools/registry.py`
- `agent/tool_guardrails.py`
- `agent/context_compressor.py`
- `tools/skill_manager_tool.py`

### 题目 B：给 Hermes 加一个“企业内部知识库”能力，你会怎么接？

优秀答案方向：

- 如果只是查询服务：优先 MCP server 或 plugin toolset。
- 如果需要长期用户画像：memory provider。
- 如果是流程型操作经验：skill。
- 如果要配置/同步：CLI command + skill。
- 避免新增 core tool，除非几乎所有用户都需要。

追问：

- 如何保证未配置时不污染工具面？
- 如何避免 prompt cache 失效？
- 如何设计权限和审计？
- 如何测试 recall 不污染其他 session？

### 题目 C：你发现 agent 在长会话中频繁空响应，如何定位？

优秀答案方向：

- 先看 role alternation 和 message repair。
- 看是否 tool result 后 empty response。
- 看 thinking-only/prefill recovery。
- 看 context overflow/compression 是否触发。
- 看 provider fallback 和 retry 分类。
- 用现有测试找相似行为，再写 regression。

证据文件：

- `agent/conversation_loop.py`
- `agent/agent_runtime_helpers.py`
- `agent/context_compressor.py`
- `tests/run_agent/test_message_sequence_repair.py`
- `tests/agent/test_empty_tool_name_loop_dampening.py`
- `tests/run_agent/test_1630_context_overflow_loop.py`

## 行为面试：如何讲这个项目

### STAR 故事 1：我如何从大型代码库抽出核心架构

S：Hermes 是一个大型 agent runtime，入口多、文件大。  
T：我要掌握 agent core 和 harness 工程。  
A：先用代码地图定位 `run_agent.py`、`conversation_loop.py`、`registry.py`、`memory_manager.py`、`skill_manager_tool.py`，再用测试验证关键不变量。  
R：产出了主链路图、harness 四象限、输出题库和证据链。

面试亮点：

- 不是“我读了很多代码”，而是“我用证据驱动拆解系统”。

### STAR 故事 2：我如何理解自进化 Agent 的安全边界

S：Agent 可以创建/修改 skills，存在失控风险。  
T：需要理解 self-improving 如何受控。  
A：追踪 `/learn`、`skill_manage`、`skill_usage`、`curator`、`curator_backup`、background review restriction。  
R：能解释自进化闭环，同时说明 guard、rollback、pinned、external skill 防线。

面试亮点：

- 能同时讲能力和治理，不只讲“自动学习很酷”。
