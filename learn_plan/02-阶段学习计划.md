# 阶段学习计划

## 使用说明

本文件负责“学什么、怎么学、读哪些代码和测试”。每个阶段的时间盒、复杂度等级、学习点数和排期，请先看 `06-时间复杂度评估.md`。

阶段速览：

| 阶段 | 主题 | 复杂度 | 预计时间 |
|---|---|---:|---:|
| 0 | 环境与仓库导航 | C1 | 1-2h |
| 1 | 一轮对话主链路 | C4 | 12-18h |
| 2 | prompt、role alternation、prompt caching | C3 | 7-12h |
| 3 | 工具系统与 harness | C4 | 12-20h |
| 4 | SessionDB、搜索、compression | C4-C5 | 20-30h |
| 5 | skills 系统 | C4 | 12-20h |
| 6 | memory 系统 | C3-C4 | 10-18h |
| 7 | 自进化闭环 | C4 | 12-20h |
| 8 | 委派、多 agent、自动化 | C4-C5 | 18-30h |
| 9 | surface 交互边界 | C3 | 4-8h |
| 10 | 综合复盘 | C4 | 8-12h |

## 阶段 0：环境与仓库导航

目标：

- 能独立找到核心入口、测试入口、配置入口。
- 知道 Windows/PowerShell 下如何跑最小测试。

必读：

- `AGENTS.md`
- `pyproject.toml`
- `README.zh-CN.md`
- `README.md`

实践：

- 列出 `agent/`、`tools/`、`plugins/memory/`、`tests/agent/` 的关键文件。
- 跑 1 个轻量测试，例如：

```powershell
.\.venv\Scripts\python -m pytest tests/agent/test_learn_prompt.py
```

通过标准：

- 写出“核心目录 10 行速记”。
- 明确 `.env` 只放 secrets，行为配置在 `config.yaml`。

## 阶段 1：一轮对话主链路

目标：

- 画出 user message 到 final response 的主流程。
- 理解 `run_agent.py` 与 `agent/conversation_loop.py` 的门面/实现关系。

必读：

- `run_agent.py`：`AIAgent.__init__` 概览、`AIAgent.run_conversation` 转发。
- `agent/conversation_loop.py`：`run_conversation` 的四段：
  - `build_turn_context`
  - 主 `while`
  - `assistant_message.tool_calls` 分支
  - no-tool final response 分支
- `agent/turn_context.py`
- `agent/turn_finalizer.py`

实践问题：

- 为什么 turn prologue 要抽到 `build_turn_context()`？
- 为什么 finalizer 要集中处理持久化和 memory sync？
- iteration budget 与 max_iterations 有什么区别？

建议测试：

```powershell
.\.venv\Scripts\python -m pytest tests/run_agent/test_tool_call_incremental_persistence.py tests/agent/test_close_interrupted_tool_sequence.py
```

产物：

- `learn_plan/notes-01-turn-loop.md`

## 阶段 2：prompt、role alternation 与 prompt caching

目标：

- 理解 Hermes 最核心的不变量：长会话的 system prompt 不能随便变。
- 理解为什么 memory/plugin recall 注入 user message，而不是 system prompt。

必读：

- `agent/system_prompt.py`
- `agent/prompt_builder.py`
- `agent/prompt_caching.py`
- `agent/conversation_loop.py` 中 API message 构造段。
- `agent/agent_runtime_helpers.py` 中 message repair 相关函数。

实践问题：

- 哪些内容是持久消息，哪些是 API-call-time only？
- role alternation 破坏后会出现什么后果？
- context compression 为什么是少数允许改变历史上下文的例外？

建议测试：

```powershell
.\.venv\Scripts\python -m pytest tests/agent/test_prompt_caching.py tests/agent/test_system_prompt_restore.py
```

产物：

- `learn_plan/notes-02-prompt-cache.md`

## 阶段 3：工具系统与 agent harness

目标：

- 理解 action space 如何被注册、裁剪、缓存和执行。
- 理解工具错误如何被转化为模型可恢复的 observation。

必读：

- `tools/registry.py`
- `model_tools.py`
- `toolsets.py`
- `agent/tool_executor.py`
- `agent/tool_guardrails.py`
- 选择 2 个具体工具读：建议 `tools/file_tools.py`、`tools/terminal_tool.py` 或 `tools/session_search_tool.py`。

实践问题：

- `registry.register()` 的参数分别保护什么？
- `check_fn` 为什么要缓存，为什么不能失败就永久隐藏工具？
- `_AGENT_LOOP_TOOLS` 为什么特殊？
- invalid tool name、invalid JSON args、empty tool name 分别如何恢复？

建议测试：

```powershell
.\.venv\Scripts\python -m pytest tests/test_model_tools.py tests/test_get_tool_definitions_cache_isolation.py tests/agent/test_tool_guardrails.py
```

产物：

- `learn_plan/notes-03-tool-harness.md`
