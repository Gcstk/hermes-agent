# 输出驱动掌握路线

## 先回答：到底要学多久

不确定要 9 周。9 周只是深度掌握路线，不是最低门槛。

| 目标 | 时间盒 | 学完后的真实效果 | 不建议做什么 |
|---|---:|---|---|
| 快速鸟瞰 | 1-2 周 | 能画出一轮 turn 主链路，知道核心文件和扩展点 | 不深挖异常恢复和插件细节 |
| 核心掌握 | 3-4 周 | 能讲清 harness、prompt caching、tools、skills、memory 的主机制 | 不逐行读 `run_agent.py`/`hermes_state.py` |
| 扎实掌握 | 6-8 周 | 能按测试解释关键行为，能写专题复盘，能判断设计取舍 | 不追求读完整个 `skills/` 和所有 provider |
| 深度掌握 | 9-12 周 | 能评审/修改类似 agent harness，能迁移设计到自己的项目 | 不把时间花在前端 surface 细节上 |

如果你的目标是“彻底了解掌握 harness 工程和 Hermes 项目”，建议按 6-8 周作为第一目标，9-12 周作为进阶目标。先达成可输出的核心掌握，再决定是否进入维护者级深挖。

## 掌握程度分级

| 等级 | 你能做到什么 | 验收方式 |
|---|---|---|
| L1 定位 | 知道功能在哪些文件 | 能列出文件职责表 |
| L2 复述 | 能按源码解释主流程 | 能画流程图并口头讲 5 分钟 |
| L3 证据化 | 能用测试证明行为 | 能说出 2-3 个测试保护了什么 |
| L4 取舍理解 | 能解释为什么这样设计 | 能写出设计收益、代价、替代方案 |
| L5 迁移应用 | 能把设计迁移到自己的 agent | 能写一份“我会如何设计自己的 harness”方案 |

真正属于你的知识至少要到 L4。只看源码到 L2 很容易产生“我懂了”的错觉。

## 费曼学习法在这个项目里的用法

每个专题都按四步走：

1. 用一句话解释：这个模块解决什么问题。
2. 讲给一个“没读过 Hermes 的工程师”：不允许引用模糊词，比如“很智能”“很复杂”，必须画流程。
3. 卡住就回源码和测试：找不到证据的句子删掉或标记为假设。
4. 重写成更简单的版本：把复杂机制压缩成 5-10 行自己的话。

每阶段固定输出：

- 一张架构图或流程图。
- 一张关键文件职责表。
- 一张“不变量/工程取舍”表。
- 一张“测试证明了什么”表。
- 一段 300-800 字的费曼讲解。
- 一个迁移问题：如果我做自己的 agent，要不要照搬 Hermes？为什么？

## 重点分层：哪些要深思，哪些只需定位

### 必须深思并认真做笔记

这些是 Hermes 和 harness 工程的精华：

- `agent/conversation_loop.py`
  - 一轮 turn 的状态机。
  - tool-call 分支、final response 分支、empty response recovery、fallback、compression 触发。
  - 笔记重点：恢复路径如何保持 role alternation，哪些消息持久化，哪些只是 API-call-time。
- `tools/registry.py` + `model_tools.py` + `toolsets.py`
  - action space 如何定义、裁剪、缓存、分发。
  - 笔记重点：为什么 core tool 要少，为什么 check_fn/service-gated tool 重要。
- `agent/prompt_builder.py` + `agent/system_prompt.py` + `agent/prompt_caching.py`
  - prompt caching、system prompt 稳定性、skills manifest、context files。
  - 笔记重点：为什么动态信息不能随便进 system prompt。
- `agent/context_compressor.py` + `hermes_state.py`
  - 长会话、超长程任务、session DB、压缩边界。
  - 笔记重点：compression 不是简单 summarize，而是保护历史结构。
- `agent/skill_commands.py` + `agent/learn_prompt.py` + `tools/skill_manager_tool.py` + `tools/skill_usage.py`
  - skills 和自进化闭环。
  - 笔记重点：过程记忆如何创建、使用、修订、归档和防误删。
- `agent/memory_provider.py` + `agent/memory_manager.py`
  - 长期记忆 provider 抽象。
  - 笔记重点：memory 与 skill 的边界，prefetch context 如何进入 turn。
- `tools/delegate_tool.py` + `tools/async_delegation.py` + `agent/moa_loop.py`
  - Subagent 与 Multi-Agent。
  - 笔记重点：子 agent 如何共享预算、继承上下文、限制工具面、回传结果。

### 需要理解但不必第一轮深挖

- `agent/auxiliary_client.py`：provider 路由、模型元数据、长进程兼容很多，第一轮只理解它服务主 loop。
- `agent/chat_completion_helpers.py`：流式/非流式 API 调用、worker thread、interrupt 细节很重要，但建议在主 loop 掌握后读。
- `plugins/memory/*`：先选 Honcho、mem0、supermemory 三个代表，不必全读。
- `cron/`：理解自然语言任务如何变成 scheduled agent turn，不必第一轮读所有平台投递。

### 可以略读/按需查

- `apps/desktop/`、`web/`、`website/`、`ui-tui/` 前端细节。
- 全量 `skills/` 内容。第一轮挑 3-5 个高质量 skill 学结构即可。
- 所有 messaging platform adapter。只需知道 gateway 复用 agent core。

## 最终目标能力矩阵

| 目标领域 | 需要掌握的代码证据 | 输出任务 | 达标表现 |
|---|---|---|---|
| 架构设计 | `run_agent.py`、`agent/conversation_loop.py`、`agent/turn_context.py`、`agent/turn_finalizer.py` | 画 Hermes agent core 总图 | 能解释一轮 turn 的入口、循环、工具、压缩、收尾 |
| Harness 工程 | `tools/registry.py`、`model_tools.py`、`toolsets.py`、`agent/tool_guardrails.py` | 写 action/observation/recovery/context budget 四象限分析 | 能判断一个新能力该做 core tool、plugin、MCP 还是 skill |
| 并发与长进程工程 | `agent/agent_init.py`、`agent/chat_completion_helpers.py`、`agent/tool_executor.py`、`agent/background_review.py` | 写线程/锁/后台任务清单 | 能解释 worker thread、interrupt、background review、tool 并发的风险 |
| 代码质量优化 | `agent/turn_context.py`、`agent/turn_finalizer.py`、`tools/registry.py` | 写“god-file 拆分路线”复盘 | 能说明哪些抽取降低了主 loop 认知负担 |
| 上下文管理 | `agent/prompt_builder.py`、`agent/system_prompt.py`、`agent/context_compressor.py` | 画 context 生命周期图 | 能区分 stable prompt、durable history、API-only injection、compressed summary |
| 长期记忆 | `agent/memory_provider.py`、`agent/memory_manager.py`、`plugins/memory/*` | 画 MemoryProvider hook 图 | 能解释 provider 如何接入 turn start/sync/session switch/pre-compress |
| Skills 与自进化 | `agent/learn_prompt.py`、`tools/skill_manager_tool.py`、`tools/skill_usage.py`、`agent/curator.py` | 画 skill 生命周期和 curator 闭环 | 能解释自进化如何受 guard、usage、backup、rollback 约束 |
| Subagent/Multi-Agent | `tools/delegate_tool.py`、`tools/async_delegation.py`、`agent/moa_loop.py`、`plugins/kanban/` | 画 parent/subagent 交互图 | 能解释 budget、toolset、session/cwd、结果回传 |
| 超长程任务 | `agent/iteration_budget.py`、`agent/context_compressor.py`、`hermes_state.py`、`cron/` | 写长任务韧性分析 | 能解释预算、压缩、持久化、恢复、调度如何配合 |

## 每周输出安排

### 第 1 周：从“能跑”到“能画主链路”

输出：

- `notes-01-turn-loop.md`
- 一张 turn loop 图。
- 一段费曼讲解：用户输入如何到 final response。

重点：

- 不追求异常分支全懂。
- 必须讲清 `run_agent.py` 与 `agent/conversation_loop.py` 的关系。

### 第 2 周：prompt caching 与 harness 入门

输出：

- `notes-02-prompt-cache.md`
- `notes-03-tool-harness.md` 初版。
- 一张 action space 生成图。

重点：

- 必须解释为什么 dynamic context 进 user message，不进 system prompt。
- 必须解释为什么 tool schema 也是上下文成本。

### 第 3-4 周：工具恢复、压缩、session

输出：

- tool recovery matrix。
- context/session 生命周期图。
- 费曼讲解：为什么 compression 不是简单总结。

重点：

- 必须读测试。
- 必须分清 durable messages、tool result、synthetic recovery scaffolding。

### 第 5-6 周：skills、memory、自进化

输出：

- skill 生命周期图。
- MemoryProvider hook 图。
- 自进化闭环图。

重点：

- 必须比较 skill 与 memory。
- 必须解释 agent-created skill 的安全边界。
- 必须说明 curator 为什么不能随便 autonomous delete。

### 第 7-8 周：subagent/multi-agent、长任务、工程质量

输出：

- parent/subagent 交互图。
- 长任务韧性分析。
- 并发/后台任务/锁清单。

重点：

- 必须解释 iteration budget 如何被 parent/subagent 共享。
- 必须说明并发工具执行和 background review 的风险。

### 第 9 周及以后：迁移与评审能力

输出：

- `Hermes harness 架构复盘.md`
- `如果我设计自己的 Agent Harness.md`
- 一份“哪些设计我会照搬，哪些不会”的取舍表。

重点：

- 不再只是复述 Hermes，而是能迁移设计。

## 输出模板：费曼讲解

每篇笔记都加这一段：

```markdown
## 费曼讲解

如果我要给一个没读过 Hermes 的工程师解释这个模块：

1. 它解决的问题是：
2. 输入是什么：
3. 输出是什么：
4. 中间最关键的 3 个步骤：
5. 最容易误解的一点：
6. Hermes 这样设计的收益：
7. 代价或风险：
8. 如果我自己实现，会保留/修改什么：
```

```markdown
|---|---|---|---|---|
|  |  |  |  |  |
```

## 输出模板：证据链

```markdown
| 我写下的结论 | 代码证据 | 测试证据 | 可信度 |
|---|---|---|---|
|  | `path.py:function` | `tests/...` | 高/中/低 |
```

规则：没有代码或测试证据的结论，只能写成“我的假设”，不能写成事实。
