# Hermes 优秀设计模块面试记录

本文档用于以面试为导向记录 Hermes 中值得学习的优秀设计模块。每个模块重点说明：设计思想、工程落地方法、优点、可改进点（如有）、风险点（如有），并补充可直接用于面试表达的回答与追问。

## 记录原则

- 先讲“为什么这样设计”，再讲“代码怎么落地”。
- 优先记录能体现工程判断的模块：缓存稳定性、窄核心、插件/技能扩展、多端复用、配置传播、安全边界、调度与长期会话等。
- 不追求逐行解释源码；忽略机械参数、简单包装函数、纯样式细节和没有设计含量的常量。
- 表达要能在面试中自然说出来：清楚、具体、口语化，但不要失去技术准确性。
- 每个结论尽量给出关键文件或文档证据。

## 模块记录模板

复制下面模板为每个模块新增一节。

```markdown
## 模块：<模块中文名>（<关键文件或英文名>）

### 面试定位
用 1-2 句话说明这个模块为什么值得在面试里讲。

### 一句话回答
给出 20-40 秒可以说完的核心回答。

### 背景与问题
说明它解决的真实问题、约束和上下文。优先讲产品/工程约束，不要只讲代码现象。

### 设计思想
说明关键抽象、边界划分、依赖方向、为什么不选更直接但更重的方案。

### 工程落地
- 入口与关键文件：列出主要文件/类/函数。
- 调用或数据流程：用短段落或列表描述主路径。
- 关键约束：列出缓存、配置、安全、并发、兼容性、测试等需要守住的点。

### 优点
说明它带来的可维护性、扩展性、用户体验、成本、可靠性或安全收益。

### 可改进点（如有）
写真实可讨论的改进方向。没有明确改进点时，写“暂无明确改进点；后续可继续观察 <具体方向>”。

### 风险点与边界
说明误用、扩展过度、缓存失效、兼容性、权限、测试盲区等风险。

### 面试追问
- Q：<可能追问>
  A：<口语化但准确的回答>
- Q：<可能追问>
  A：<口语化但准确的回答>

### 证据索引
- `<path>`：说明这里提供了什么证据。
- `<path>`：说明这里提供了什么证据。
```
