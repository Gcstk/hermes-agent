# Hermes 面试导向学习笔记

> 以系统设计面试的视角，记录 Hermes Agent 中的优秀设计模块。
> 每个模块从"面试官会怎么问"出发，用口语化的方式讲清楚：为什么这么设计、怎么落地的、好在哪、有什么坑。

## 为什么要这样记录？

传统的源码阅读笔记容易变成"功能罗列"——知道了有什么，但说不清**为什么**。
面试官不关心你用了什么库，他们关心的是：

1. **你遇到了什么问题？**（设计背景）
2. **你为什么选这条路？**（trade-off 分析）
3. **你怎么落地的？**（工程实现）
4. **回头看你有什么反思？**（优点/改进/风险）

这套笔记就是为了帮你建立这种**结构化表达**的能力。

## 写作原则

- **口语化**：写的时候想象你对面坐着面试官，你在白板上边画边讲
- **抓核心矛盾**：每个模块只讲 2-3 个关键设计决策，别面面俱到
- **先有结论再展开**：每段开头先给结论，再解释为什么
- **用"我们"而不是"代码做了"**：面试是人在讲故事，不是文档在念
- **证据轻量定位**：证据索引只写关键文件、类名、方法名，方便后续回源码复习；不要贴代码片段，也不要列太多
